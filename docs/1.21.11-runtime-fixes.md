# 1.21.11 运行时错误解决记录

> **仅适用于 ver/1.21.11 分支**。本文件记录迁移/运行时修过的错误与原因，供按需查阅，不放入 CLAUDE.md（避免占用系统提示词）。
> 排查对应问题时先看本文件，往往有现成结论。

## GUI blit 语义（custom_ui 渲染）
- **`GuiGraphics.blit` 重载在 1.21.11 变化巨大**，SSC custom_ui 的 blit 调用多为 1.21.1 旧语义 → 贴图空白/错位（"有文字无贴图"）。
- 1.21.1 有**两个** 9 参 blit（UV 在前 `(id,x,y,u,v,w,h,texW,texH)` 和尺寸在前 `(id,x,y,w,h,u,v,texW,texH)`，SSC 代码混用）；**1.21.11 只保留一个 9 参** `(id,x1,x2,y1,y2,u1,u2,v1,v2)`（归一化 UV，语义完全不同）→ 旧调用被 reinterpret 成宽高 0/UV 错位 → 空白。
- **正确用法（1.21.11）**：带管线 13 参 `blit(RenderPipelines.GUI_TEXTURED, id, x, y, u, v, width, height, uWidth, vHeight, texW, texH, color)`（像素 UV，内部归一化 u1=u/texW 等）。uWidth/vHeight 是 **UV 区域尺寸**（≠0，通常=显示宽高）。
- 转换：1.21.1 的 `blit(id, x, y, u, v, w, h, texW, texH)` → `blit(GUI_TEXTURED, id, x, y, u, v, w, h, w, h, texW, texH, -1)`。注意各调用实际是 UV 在前还是尺寸在前（看意图）。
- 已修文件：`custom_ui/` 全部（StartBookScreenV2、BookOfShapeShifterScreenV2_P1/P2、FormColorSelectMenu(V2)、NormalFormSelectScreen、PatronFormSelectScreen、ScaleScrollTextWidget、SimpleIntSliderWidget、FCS_ButtonWidget）+ `player_form/utils/InstinctBarRenderer`（本能条条纹！）+ `mana/`（FamiliarFoxManaBar、WebResourceBar、InstinctBarLikeManaBar）+ `integration/origins/screen/`（OriginDisplayScreen、CraftingRecipeTooltip）+ `render/tech/ItemStorePowerRender`。
- **教训：批量正则转换 blit 时 `[^,]+` 会匹配换行导致跨行误改**（把 `if(...)` 也改了）。必须用 `[^,\n]+`（不含换行），Math.max 等含逗号参数手动处理。转换后立即 IDE 构建验证。

## vanilla 花效果重复（创造物品栏崩）
- **vanilla 1.21.11 的花（FlowerBlock）效果本身有重复**：SATURATION 0.35F×2（蒲公英/兰花）、NIGHT_VISION 5.0F×2（火把花/虞美人）、WEAKNESS 7.0F×4（四色郁金香）。`CreativeModeTabs.generateSuspiciousStews` 生成谜之炖菜时，相同效果的花生成相同 `SUSPICIOUS_STEW_EFFECTS` 组件 → `ItemStackLinkedSet` 报 **"Accidentally adding the same item stack twice"** 崩（打开创造物品栏触发）。
- **修复**：`mixin/CreativeModeTabsSuspiciousStewMixin`（ssc-misc）`@Redirect` `set.add(stack)`，用静态 `Set<SuspiciousStewEffects>` 手动去重跳过重复效果，`@Inject HEAD` 每次调用前清空 seen。这是 vanilla bug，无 mod 环境理论上去重应成功，但实际环境可能触发。

## 反射字段陷阱（运行时 intermediary 混淆名）
- **运行时（knot）字段/方法是 intermediary 混淆名（field_xxx/method_xxx）**，Java 反射字符串（`getDeclaredField("provider")` 等）**不被映射** → `NoSuchFieldException`。IDE/编译用 mojmap 名，但反射在运行时失效。
- 典型：`custom_ui/ui_part/ScaleTextRenderer` 之前反射 `Font.class.getDeclaredField("provider")` → 开书界面崩。**修复**：新建 `mixin/FontAccessor`（`@Mixin(Font.class)` + `@Accessor("provider")`，mixin 处理器会映射字段名），`super(((FontAccessor) font).getProvider())`。注册到 ssc-misc.mixins.json 的 `client` 数组。
- **凡是反射访问 vanilla 字段/方法的代码，都应改用 mixin @Accessor/@Invoker**（会被 remap 到 intermediary 名）。

## 实体属性注册（TemptingSensor 崩服）
- **自定义实体（extends Axolotl/Bat/Ocelot/Wolf 等 Animal）的 `createAttributes()` 必须用对应基类方法**：`Animal.createAnimalAttributes()`（= `Mob.createMobAttributes().add(TEMPT_RANGE, 10.0)`）。若用 `Mob.createMobAttributes()` 缺 `minecraft:tempt_range` → 服务端 tick 崩 `Can't find attribute minecraft:tempt_range`（TemptingSensor.doTick 访问）。Monster 子类（如 Spider）用 `Monster.createMonsterAttributes()`。
- 已修：`form_giving_custom_entity/` 下 5 个 Transformative 实体（axolotl/bat/ocelot/wolf → Animal，spider → Monster）。

## 数据包/资源层运行时坑（Apoli-Legacy 2.12.10 = 1.20 移植）
- **Apoli-Legacy 2.12.10 + Calio-Legacy 1.11.2 是 1.20 时代的代码**，与 1.21.1 用的官方 Apoli alpha.7/Calio 1.14 差异巨大。数据加载失败多为"1.20 数据格式/API 语义"与 1.21.11 不匹配，报错不会崩服但功能失效。
- **Origin icon `provider is null`**：Calio 1.11.2 的 `ITEM_STACK` 解析用 `provider.createSerializationContext(JsonOps.INSTANCE)`，provider 为 null 就 NPE → 所有 Origin 文件加载失败 → "Registry contains 1 origins" → form 加载报 `not registered`。**修复**：`Origins.registerResourceListeners` 用 `manager.registerWithRegistries(id, OriginManager::new)`（Calio 的 `ReloadableServerResourcesMixin` 注入完整 `HolderLookup.Provider`），`OriginManager` 构造接收 provider 传给 `Origin.fromJson`。Apoli 的 `PowerTypes` 同样走 `registerWithRegistries`。
- **Recipe key 值格式**：1.21.11 的 `Ingredient.CODEC = HolderSetCodec.create(Registries.ITEM, Item.CODEC, false)` 只接受**字符串/数组**，不接受 `{"item": "..."}` 对象 → `No key fabric:type` / `List is too short`。修复：递归把 `{"item": X}`→`"X"`、`{"tag": X}`→`"#X"`（`src/main/resources/data/shape-shifter-curse/recipe/` 42 个文件已转）。注意 `SpawnerData`/自定义 recipe 同规则。
- **命名空间别名**：2.12.10 没有 `PowerFactories.ALIASES`，用 `NamespaceAlias.addAlias("origins", "apoli")`（`io.github.apace100.apoli.util.NamespaceAlias`，覆盖 power/condition/action 类型解析，见 `PowerTypes.readPower`）。**SSC 的 `OriginsPowerTypes.register()` 必须调用**，否则 `origins:toggle` 等找不到（`apoli:toggle` 本身已注册）。
- **`apoli:modify_type_tag` 需 SSC 自注册**：2.12.10 无此 power type（1.21.1 的 `OriginsPowerTypes` 注册过，迁移时丢失）。在 `OriginsPowerTypes.register()` 恢复注册（data: `tag`=ENTITY_TAG，用 `ModifyTypeTagPower`）。
- **modifier operation 命名空间**：2.12.10 的 `ModifierOperations.registerAll()` 用 `Identifier.parse(name)` → 注册成 **`minecraft:set_total`** 而非 `apoli:set_total`。**SSC 数据已去 `apoli:` 前缀**（`set_total`/`min_base`/`min_total` 走 `minecraft:` 注册表，天然兼容）。⚠️ **不能给 `ApoliRegistries.MODIFIER_OPERATION` 注册 `apoli:` 别名**——`MappedRegistry.register` 检查**值重复**，`ModifierOperation.SET_TOTAL` 枚举已被 `minecraft:set_total` 占用，再注册 `apoli:set_total` 抛 `Adding duplicate value 'SET_TOTAL' to registry` 崩服。
- **attribute modifier 的 operation 走 vanilla 枚举**：`attribute`/`conditioned_attribute` 的 modifier 用 `ApoliDataTypes.ATTRIBUTED_ATTRIBUTE_MODIFIER`，其 operation 用 Calio `MODIFIER_OPERATION` = **vanilla `AttributeModifier.Operation` 枚举**（兼容映射 `addition→ADD_VALUE`、`multiply_base→ADD_MULTIPLIED_BASE`、`multiply_total→ADD_MULTIPLIED_TOTAL`，也原生支持 `add_value/add_multiplied_base/add_multiplied_total`）。SSC 数据用旧名（`addition`/`multiply_base`/`multiply_total`），`name` 字段（非 `id`，schema 无 id 字段）。
- **particle JSON 已回退到 1.20 字符串格式**：数据用 `"particle": "minecraft:nautilus"`（无参字符串）或 `{"type": "minecraft:dust", "params": "0.07 0.07 0.07 2"}`（字符串 params）——**Calio-Legacy 原生解析器支持**（`PARTICLE_EFFECT_OR_TYPE` 字符串分支 + `LegacyParticleOptionFactory` 用 `StringReader` 解析 "r g b s" 格式）。`mixin/CalioParticleEffectMixin`（ssc-misc）现在只兜底 **1.21 遗留格式**（对象 params / 无 params 对象），字符串格式走原生解析。**注意**：上游粒子格式混用（有对象无 params 如 `{"type":"minecraft:soul_fire_flame"}`），对象无 params 在 Calio-Legacy 下会崩（`get("params")` null）→ 同步上游时需转字符串或依赖 mixin 兜底。
- **`SpawnerData` record 语义变化（会崩服）**：1.21.11 `MobSpawnSettings.SpawnerData` 是 `record (EntityType, int minCount, int maxCount)`，**weight 移到 `WeightedList`**。1.20 的 `new SpawnerData(type, weight, min)` → 迁移后 `new SpawnerData(type, 20, 3)` 变成 **minCount=20, maxCount=3** → `NaturalSpawner.spawnCategoryForPosition` 里 `nextInt(1+maxCount-minCount)` = `nextInt(-16)` → **`IllegalArgumentException: Bound must be positive` 崩服**（结构 spawn 触发）。修复：`WeightedList.<SpawnerData>builder().add(new SpawnerData(type, min, max), weight).build()`。Java 构造绕过 CODEC 的 `minCount ≤ maxCount` validate。
- **`Item.CODEC` 拒绝 air**：1.21.11 `Item.CODEC` 有 `.validate(... Items.AIR → "Item must not be minecraft:air")`。数据里 `totem_stack: {"item": "minecraft:air"}` 解析失败，改用有效物品（如 `totem_of_undying`）。

## 刷怪蛋（Spawn Egg）紫黑 + 放不出实体
- **`minecraft:item/template_spawn_egg` parent 在 1.21.11 被移除** → 用它的刷怪蛋模型加载失败 → 紫黑。修复：改用 `parent: minecraft:item/generated` + `layer0/layer1`（SSC 用 `textures/item/spawn_egg.png` + `spawn_egg_overlay.png`）。已修：`models/item/custom_*_spawn_egg.json` 5 个。
- **1.21.11 的 `SpawnEggItem(Item.Properties)` 从 `DataComponents.ENTITY_DATA`（`TypedEntityData<EntityType>`）读实体类型**，不再用构造传 EntityType。`SpawnEggItem::new` 没设置 → `getType` 返回 null → 放不出实体。修复：`props.component(DataComponents.ENTITY_DATA, TypedEntityData.<EntityType<?>>of(T_XXX, new CompoundTag()))`。`TypedEntityData` 构造是 package-private，**必须用 `TypedEntityData.of(...)` 工厂**。已修：`RegTransformativeEntitySpawnEgg`。

## 模型 particle 纹理引用缺失（WARN 刷屏）
- 带 elements 的模型（Blockbench 导出）缺 `particle` 纹理引用 → `Missing texture references in model ...: particle` WARN。修复：textures 里加 `"particle": "shape-shifter-curse:item/xxx"`。已修：`web_projectile`、`book_of_shape_shifter`、`cursed_book_of_shape_shifter`。

## GeoBone.hashCode 无限递归（StackOverflow）
- **GL5 的 `GeoBone.hashCode` 是缺陷**：`Objects.hash(parent, ..., Arrays.hashCode(children), ...)`——child 的 hash 含 parent，parent 的 hash 又含 children → **任何有父子关系的树都会无限递归**（StackOverflow）。
- **绝不能把 GeoBone 放进 HashSet/HashMap（会调 hashCode）**。SSC 触发点：`FormRenderFeature.hideNonArmBones` 的 `Set<GeoBone> ancestors = new HashSet<>()` → `add(bone)` 崩。**修复**：改用 `Collections.newSetFromMap(new IdentityHashMap<>())`（引用比较，不调 hashCode）。

## ClientAsset.ResourceTexture 路径（皮肤 Missing resource）
- `ClientAsset.ResourceTexture(id)` 会自动 `"textures/" + id.path + ".png"`。**传 id 时必须用纯路径**（`entity/base_player/ssc_base_skin`），传 `textures/entity/...png` 会变 `textures/textures/...png.png` 加载失败（Missing resource WARN）。
- 已修：`AbstractClientPlayerEntityMixin.getSkin` 的 CUSTOM_SKIN 改纯路径。
